# TOP WRITER PRO V6.0

长篇小说全流程生产主控系统，一个 AI Agent Skill。

不是「写小说的提示词」，而是一套带质量门槛的生产流程：统筹剧情导演、人物模拟、世界模拟、读者模拟、语言精度、连续性、数据治理、工程 QA 八个子系统，按 STEP 01–12 流水线产出章节正文与检查报告。

## 它解决什么问题

AI 写长篇最常见的四种崩法，本技能逐条对治：

| 崩法 | 对治模块 |
|---|---|
| 人物为了推剧情犯蠢 | 02 人物模拟 —— 人物按自己的利益与认知决策，允许拒绝、欺骗、背叛主角 |
| 世界只在主角到场时运转 | 03 世界模拟 —— 规则卡必填「代价」与「可观察现象」，主角不在场时世界照样变 |
| 前后矛盾、伏笔丢了 | 06 连续性 —— 14 项检查表 + 伏笔台账 + 最小修复原则 |
| 文字很油、形容词堆砌 | 05 语言质量 —— 福楼拜八项精度检查 + 八类废话清单 + 量化阈值 |

```

├── SKILL.md                      调度 / 流水线 / 质量门槛 / 冲突仲裁

    ├── 02-character-simulator.md  人物卡 13 字段、决策推演、认知隔离台账
    ├── 03-world-simulator.md      规则卡 7 字段、自主运行台账、底层自检
    ├── 04-reader-simulator.md     三档读者、11 项量表、P0–P3 分级
    ├── 05-language-quality.md     福楼拜八项、废话清单、段落功能标注
    ├── 06-continuity.md           14 项检查、冲突登记、伏笔台账

`SKILL.md` 始终加载；`references/` 按任务按需读取，不全量进上下文。

  ~/.workbuddy/skills/top-writer-pro
```

项目级（仅当前仓库）：

```bash
git clone https://github.com/<your-name>/top-writer-pro.git \
  .workbuddy/skills/top-writer-pro
```

装完确认目录下有 `SKILL.md` 且 frontmatter 的 `name` 为 `top-writer-pro`。

## 使用

说题材就开写，或者直接说：

- 「开书」「定设定」「世界观」→ 读 03 + 02
- 「出卷纲」「细纲」「卡文」→ 读 01 + 02
- 「写第 X 章」→ 读 01+02+03，写完再读 04+05+06
- 「改这章」「去 AI 味」→ 读 05 + 04
- 「查连续性」→ 读 06 + 07
- 「读者视角审一下」→ 读 04

## 交付纪律

- 正文落 `正文/`，一章一文件；设定落 `设定/`
- 新写入内容默认 `PROPOSED`，用户认可后才 `CONFIRMED`
- 模拟读者结论只能写成「按 X 档位判读，此处可能劝退」，不编造追读数据
- 未实际执行的测试不得报告为通过；未真实连接的服务不得报告为已连接

## 关于工程化部分

本技能的 07 / 08 两个模块刻意保留了数据库与 QA 的工程口径（五逻辑域、五状态、备份/迁移/回读/证据链）。但需要说清楚：**技能本身是文档层，不含任何可执行引擎**。附带的工程核验记录属于基线审计，不代表存在一个能自动写小说的程序。

写作能力来自判读流程，不来自代码。
